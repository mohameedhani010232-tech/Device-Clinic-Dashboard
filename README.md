# نظام عيادة جهاز مدينة العبور — MongoDB مركزي

هذه النسخة تعتمد على **MongoDB كمصدر وحيد لبيانات المرضى والروشتات والتحاليل**. أي جهاز يفتح نفس الرابط ويُسجل الدخول يرى نفس البيانات المركزية. لا يتم تخزين بيانات المرضى في `localStorage`.

## أهم ما تم إصلاحه

- حماية جميع عمليات API بتسجيل دخول حقيقي من السيرفر، وليس مجرد إخفاء الصفحة.
- جلسة دخول موقعة ومحددة المدة.
- تحديد محاولات تسجيل الدخول لمنع التخمين السريع.
- MongoDB هي المصدر الوحيد للحقيقة.
- إزالة اعتماد المشروع على Supabase القديم.
- منع اعتماد الواجهة على نسخة محلية قديمة من بيانات المرضى.
- مزامنة مركزية تلقائية كل 15 ثانية، بالإضافة إلى التحديث عند الرجوع للصفحة.
- الحفظ والتعديل والحذف لا يتم اعتباره ناجحًا إلا بعد تأكيد الخادم.
- إصلاح ربط رقم البطاقة الشخصية بالبيانات الصحيحة.
- منع تكرار الرقم الطبي ورقم البطاقة برسائل واضحة، ومعالجة أي فهرس قديم غير صحيح للبطاقة الشخصية.
- منع إنشاء مرضى وهميين عند حفظ الروشتة أو طلب التحليل لمعرف غير موجود.
- إضافة مهلة للطلبات من الواجهة حتى لا تظل أزرار الحفظ معلقة بلا نهاية.
- إضافة `package-lock.json`.
- `start.bat` يشغل الخادم المركزي بدلًا من خادم ملفات ثابت لا يستطيع الوصول إلى API.

## التشغيل على جهاز الخادم

1. ثبّت Node.js.
2. انسخ `.env.example` إلى `.env`.
3. ضع رابط MongoDB الحقيقي في `MONGODB_URI`.
4. ضع كلمة المرور التي تريدها في `APP_PASSWORD`.
5. ضع قيمة عشوائية طويلة في `APP_SESSION_SECRET` (32 حرفًا على الأقل).
6. شغّل:

```bash
npm install
npm start
```

ثم افتح:

`http://localhost:5000`

## أجهزة أخرى على نفس الشبكة

الخادم يستمع على `0.0.0.0`، لذلك بعد معرفة IP لجهاز الخادم، افتح من جهاز آخر:

`http://IP-جهاز-الخادم:5000`

كل الأجهزة تستخدم **نفس MongoDB**، وبالتالي البيانات ليست منفصلة لكل جهاز.

## النشر على الإنترنت

يمكن نشر المشروع على Vercel باستخدام `api/index.js` و`vercel.json`. في إعدادات المشروع على منصة الاستضافة يجب ضبط:

- `MONGODB_URI`
- `APP_PASSWORD`
- `APP_SESSION_SECRET`
- `SESSION_HOURS` (اختياري، الافتراضي 12 ساعة)

**لا ترفع ملف `.env` إلى GitHub.** استخدم متغيرات البيئة في منصة الاستضافة.

## مهم جدًا للبيانات الطبية

لا تجعل رابط النظام متاحًا للعامة بدون حماية. النظام الآن يسمح لأي جهاز يملك الرابط **بعد إدخال كلمة المرور** بالوصول إلى البيانات المركزية، أما API نفسه فلا يقبل قراءة/إضافة/تعديل/حذف بدون جلسة دخول صحيحة.

يجب أيضًا تفعيل نسخ احتياطية دورية لقاعدة MongoDB قبل التشغيل الفعلي.
